# Baltasar Campos — Portfolio Site

A personal portfolio built with **Astro 5**, **React 18**, **TypeScript**, **Tailwind CSS 3**, and **Framer Motion**. Deployed to **Netlify** as a static site with a serverless contact-form endpoint.

## Getting Started

**Prerequisites:** Node.js ≥ 22, npm ≥ 10

```bash
# 1. Clone the repository, including the content/ submodule
git clone --recurse-submodules https://github.com/BaltasarCampos/Portfolio.git
cd Portfolio

# (already have a clone without submodules? run this instead)
git submodule update --init

# 2. Install dependencies
npm install

# 3. Copy environment variables
cp .env.example .env.local
# → Fill in your values (see Environment Variables section)

# 4. Start the dev server
npm run dev
# → http://localhost:4321
```

> **Note:** The contact form POSTs to `/api/contact`, which is redirected to the Netlify function via `netlify.toml`. In local development, use the [Netlify CLI](https://docs.netlify.com/cli/get-started/) (`netlify dev`) to run the function locally.

> **Note:** All authored content (project entries, hero/about/contact copy, project images) lives in a separate private repository, [`portfolio-content`](https://github.com/BaltasarCampos/portfolio-content), attached here as a git submodule at `content/`. `git submodule update --init` uses your own GitHub access to that repo — no extra credentials are needed for local development. See [Customising Content](#customising-content).

## Environment Variables

Copy `.env.example` to `.env.local` and set each value:

| Variable | Required | Description |
|----------|----------|-------------|
| `RESEND_API_KEY` | ✅ | Resend API key for sending email (starts with `re_`) |
| `ENGINEER_EMAIL` | ✅ | Your email address — where submissions are delivered |
| `FROM_EMAIL` | ✅ | Verified Resend sender address (or `onboarding@resend.dev` for testing) |
| `RATE_LIMIT_MAX_PER_HOUR` | optional | Max contact form submissions per IP per hour (default: `3`) |
| `PUBLIC_SITE_URL` | optional | Canonical site URL for CORS (default: `http://localhost:4321`) |

### Setting variables on Netlify

1. Go to **Site configuration → Environment variables**
2. Add each variable from the table above
3. Redeploy — variables are injected at function runtime

## Customising Content

Project entries, page copy (hero/about/contact), and project images are **not** stored in this repository. They live in the private [`portfolio-content`](https://github.com/BaltasarCampos/portfolio-content) repository, attached here as a git submodule at `content/`, and are read at build time via [Astro Content Collections](https://docs.astro.build/en/guides/content-collections/) (schema: `src/content/config.ts`).

To edit content, work inside `content/` — no changes to this repository's source code are needed:

```
content/
├── projects/
│   └── <id>.yaml       # one file per project entry
├── copy/
│   ├── hero.yaml
│   ├── about.yaml
│   └── contact.yaml
└── images/projects/
    └── <id>-<width>w.<ext>   # 400/800/1200w, jpg + webp
```

```bash
cd content
# add or edit a projects/*.yaml or copy/*.yaml file
git add -A && git commit -m "…" && git push
cd ..
git add content && git commit -m "update content submodule pointer"
npm run build   # or npm run dev — validates against the schema and fails loudly on any error
```

Field-level schema (required/optional, length limits, allowed categories) is documented in [`specs/002-content-decoupling/contracts/content-repository-contract.md`](specs/002-content-decoupling/contracts/content-repository-contract.md) and enforced in `src/content/config.ts`. A missing/invalid field or a `thumbnail.src` with no matching image variant fails the build with a specific error rather than shipping broken content.

New project images are optimized and committed directly in the `portfolio-content` repository — see [Image Optimisation](#image-optimisation).

### Navigation links (`src/data/navigation.ts`)

Structural, not content — add or reorder sections by editing the `navItems` array directly in this repository.

## Image Optimisation

Image optimization lives in the [`portfolio-content`](https://github.com/BaltasarCampos/portfolio-content) repository, not here. Drop original high-resolution images (JPEG/PNG/WebP) into that repository's `images/projects/src/`, then run `npm run optimize-images` there — it uses **Sharp** to generate responsive variants at 400 w, 800 w, and 1200 w in both WebP and JPEG formats, landing directly in `images/projects/` (i.e. `content/images/projects/` from this repository). Commit and push in `portfolio-content`, then bump the submodule pointer here (see [Customising Content](#customising-content)).

`public/images/projects/` in this repository is gitignored and entirely regenerated from `content/` on every build by `scripts/sync-content-images.ts`.

## Deployment

### Continuous deployment (recommended)

1. Push this repository to GitHub
2. In Netlify: **Add new site → Import from Git**
3. Build command: `npm run build`
4. Publish directory: `dist`
5. Add environment variables (see [Environment Variables](#environment-variables))
6. Add a `CONTENT_REPO_TOKEN` environment variable — a read-only, fine-grained GitHub PAT scoped to the private `portfolio-content` repository. Netlify's build command uses it to authenticate the `content/` submodule checkout (see `netlify.toml`).
7. Deploy ✅

The included **GitHub Actions** workflows run type-check, lint, and tests on every push. The `build.yml` workflow also needs the same `CONTENT_REPO_TOKEN` added as a **repository secret** (Settings → Secrets and variables → Actions) so it can check out the private submodule during CI.

### Contact form

The form POSTs to `/api/contact`, redirected by `netlify.toml` to `/.netlify/functions/contact`. The function validates input, checks the honeypot, enforces rate limiting (3 req/IP/hr), and sends email via **Resend**.

For local development, run with [Netlify CLI](https://docs.netlify.com/cli/get-started/):

```bash
npx netlify dev
```

## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
/
├── public/
├── src/
│   └── pages/
│       └── index.astro
└── package.json
```

Astro looks for `.astro` or `.md` files in the `src/pages/` directory. Each page is exposed as a route based on its file name.

There's nothing special about `src/components/`, but that's where we like to put any Astro/React/Vue/Svelte/Preact components.

Any static assets, like images, can be placed in the `public/` directory.
